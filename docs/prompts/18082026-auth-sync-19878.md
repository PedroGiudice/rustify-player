# Pickup: fail-closed na porta 19878 (token Bearer no sync S24→desktop)

## Contexto rápido

Rustify Player (Tauri 2.x, Rust + SolidJS; o mesmo repo produz desktop Linux e
APK Android). O receptor de sync (`src-tauri/src/sync_receiver.rs`, porta 19878
no IP tailscale da cmr-auto) aceita POST de `play_events` **sem credencial** —
é o único write-path aberto do sinal de produção (CMR-194). Decisão do CEO
(2026-08-18): fechar com token Bearer de máquina, AGORA, na ordem sem janela
de 401. Biometria foi descartada com racional (worker em background não tem
humano presente) — não reabrir. Contexto completo:
`docs/contexto/18082026-auth-sync-19878.md`.

**Regras do repo que valem aqui:** não compilar até acumular as edições
(`cargo check` pontual ok); `bun run build` manual ANTES de
`cargo tauri android build --debug`; release desktop = bump de versão em
`tauri.conf.json` ANTES de `./scripts/release.sh`; o CEO instala o .deb com
`dpkg -i` e o APK com `adb install -r` — lembrar ele.

## Ordem das fases (a segurança está NA ordem — não trocar)

### Fase 1 — celular passa a enviar o token (~45min)

**`scripts/android/export_manifest.py`** (âncora: bloco `--deploy`, ~linha
490, que faz `ssh cmr-auto mkdir -p {STAGING}/.rustify` + scp dos 4 artefatos):

- Antes do scp: garantir o token na cmr-auto —
  `ssh cmr-auto 'test -f ~/.local/share/dev.cmr.rustifyplayer/sync-token || (umask 077 && openssl rand -hex 32 > ~/.local/share/dev.cmr.rustifyplayer/sync-token)'`
- Baixar uma cópia (`scp cmr-auto:...sync-token {out_dir}/sync-token`) e
  incluí-la na lista de artefatos enviados pro staging `.rustify/`. Vira o 5º
  arquivo do mesmo trilho que o `phone_push_retry.sh` já empurra pro aparelho.

**`src-tauri/src/mobile_sync.rs`** (âncoras: fn `endpoint()` — padrão de
config — e `sync_once()`, onde o `ureq::post` acontece):

- Fn `token(data_dir) -> Option<String>` com precedência:
  1. `<data_dir>/sync.json` campo `"token"` (override manual, privado);
  2. cópia privada `<data_dir>/sync-token`;
  3. `/sdcard/Music/.rustify/sync-token` (via `mobile_library::MUSIC_ROOT`) —
     e ao ler daqui, **copiar pro data dir privado** (mitigação do sdcard
     legível; a partir daí vale a 2).
  Trim no conteúdo (arquivo pode vir com \n). Sem token → `None`, header não
  vai — comportamento de hoje, zero risco de quebrar o sync existente.
- No `sync_once`: `let req = ureq::post(url).timeout(...);` + `.set("Authorization", &format!("Bearer {t}"))` quando `Some`.
  O token resolve UMA vez no spawn (junto de device_id/app_version), não a
  cada ciclo.
- Teste host: precedência da resolução (sync.json > privado > sdcard) e trim —
  fn pura com `tempfile`, mesmo padrão dos testes existentes do módulo.

**Entrega da fase:** `bun run build` + APK debug + instalar no S24; rodar
`python3 scripts/android/export_manifest.py --deploy --skip-covers` + o
`phone_push_retry.sh` na cmr-auto pra levar o token; confirmar no log do app
(`adb shell run-as dev.cmr.rustifyplayer tail logs/rustify-player.log`) que o
sync segue entregando (`mobile-sync: lote entregue`).

### Fase 2 — receptor verifica e LOGA, aceitando tudo (~45min)

**`src-tauri/src/sync_receiver.rs`:**

- Const `REQUIRE_BEARER: bool = false` no topo (o flip da fase 3 é 1 linha).
- `start()` ganha o carregamento do token: `<app_data_dir>/sync-token` — o
  caller em `desktop.rs` já tem `AppHandle`; passar `Option<String>` por
  `start`/`start_on` até `handle()`.
- Em `handle()`, rota POST: extrair `authorization` do mesmo iterador `lines`
  que já pega `content-length`. Comparar com o esperado
  (`Bearer <token>`, comparação simples — o canal é a tailnet cifrada, não
  precisa de constant-time aqui, mas `subtle` é barato se quiser).
- Lógica:
  - token do desktop AUSENTE → comporta como hoje (accept), loga
    `sync auth: sem token configurado` uma vez no boot;
  - header confere → `tracing::info!("sync auth ok")` junto do
    `lote processado`;
  - header ausente/errado → `tracing::warn!("sync auth FALHOU — aceitando (observação)")` e aceita, porque `REQUIRE_BEARER=false`.
- `respond()` ganha o 401 (`"Unauthorized"`).
- Testes (padrão `fake_qdrant` + `start_on("127.0.0.1:0")`): com token
  configurado e header certo → 200; header errado com REQUIRE=false → 200 (e
  é o teste que a fase 3 vai inverter); sem token configurado → 200.

**Entrega da fase:** bump de versão + `./scripts/release.sh`; CEO instala na
cmr-auto (`dpkg -i` + restart do app). Observar ≥1 dia: o log do desktop deve
mostrar `sync auth ok` nos lotes do S24. Se aparecer `auth FALHOU`, o token
não chegou ao aparelho — resolver ANTES da fase 3 (é exatamente pra isso que a
fase de observação existe).

### Fase 3 — fail-closed (~15min + release)

- Flip `REQUIRE_BEARER = true`; header ausente/errado → 401 sem processar o
  body. Inverter o teste da fase 2 e adicionar: 401 não incrementa
  accepted/rejected.
- Bump + release + dpkg. **Validação externa real** (padrão da regra de
  firewall): da VM, `curl -s -o /dev/null -w '%{http_code}' -X POST http://100.102.249.9:19878/sync/events -d '{"events":[]}'`
  → 401; com `-H "Authorization: Bearer $(ssh cmr-auto cat ~/.local/share/dev.cmr.rustifyplayer/sync-token)"`
  → 200. E o log do S24 seguindo com `lote entregue`.

### Fase 4 — fechamento (~20min)

- CMR-194: comentar as três fases com evidência (log ok / curl 401) e fechar.
- Docs vivas: `docs/android/ipc-contrato-v0.md` (seção do sync ganha o
  parágrafo do Bearer), CLAUDE.md do repo (a exceção da 19878 no bloco de
  superfície de rede menciona "sem auth" implícito — registrar o token), e no
  plano de paridade marcar D8 como parcialmente antecipado (a parte de auth).
- `docs/contexto/18082026-auth-sync-19878.md`: apêndice "como rodou".

## Armadilhas conhecidas

- **Não inverter a ordem das fases** — fechar o desktop antes do APK com token
  = sync 401 e o journal do aparelho acumulando até alguém notar.
- O receptor parseia HTTP na mão: o nome do header chega em qualquer caixa
  (`Authorization`/`authorization`) — usar `eq_ignore_ascii_case` como o
  content-length já faz.
- `phone_push_retry.sh` usa `adb push --sync` (só copia se mudou) — token novo
  copia; token igual não re-copia, e está certo assim.
- O S24 cai do adb com frequência nesta infra — se o push falhar, o sync
  existente NÃO quebra (fase 1 é aditiva); só a observação da fase 2 fica
  esperando.
- Log do desktop na cmr-auto: `~/.local/share/dev.cmr.rustifyplayer/logs/`.
